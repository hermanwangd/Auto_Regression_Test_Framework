# Portable source bundles and bounded evidence collection

The tool remains the existing framework runner plus an external pinned case/config/data bundle. The SUT stays external. No SUT executable, runtime image, credentials or product source is built into this capability. `runner-package` admits immutable source definitions; it does not run tests, evaluate an oracle or grant deployment/release authority.

Executable cases/config/sanitized data/oracles stay in their owning product/service repositories. Cross-service SIT has one main-flow-owned root in **one existing product repository**: `tests/sit/{suite.yaml,cases/,config/,data/,dependencies.lock}`. Service cases remain in service repositories and are referenced by qualified repo/commit/path/test-ID and byte SHA. Tool unit/contract/public examples stay here. ProductKnowledge carries curated relationships and immutable source references; Cognee is an index. Neither is executable SSOT. Actual company owner/repository URLs remain unbound until supplied. Do not create a new product repository or maintain source copies in ProductKnowledge.

## Source admission

Use the authoritative [lock schema](../02-architecture/contracts/dependencies_lock.v1.schema.yaml) and [source binding schema](../02-architecture/contracts/source_bindings.v1.schema.yaml). A protected trusted-root binding maps only already checked-out authorized roots to exact Git commits. No fetch/clone/network/root discovery occurs. The independent expected lock/root digests come from trusted invocation configuration, outside editable test/PK requests; hashes alone are integrity, not semantic approval.

```text
regress runner-package --dependencies-lock <main-root/tests/sit/dependencies.lock>
  --expected-lock-sha256 <independent-lock-pin>
  --roots-binding <protected-trusted-roots.json>
  --expected-roots-sha256 <independent-root-binding-pin>
  --out <fresh-private-output>
```

This new same-framework command returns `source_bindings_json`/SHA and `bundle_manifest`/SHA. The metadata excludes private root paths and executable/source/context contents. Materialized files are DERIVED snapshots; the original sources are not rewritten. Each committed input and lock must have regular Git mode100644/100755 as well as safe current filesystem type; equal symlink-blob bytes cannot pass. Multiple qualified IDs may bind the same immutable physical payload, copied once while every logical identity remains present. Missing repo/owner/path/commit/hash/data/oracle/cleanup owner, unsafe paths/types/links, graph inconsistencies or changed pins block admission. Limits are16 repositories,128 artifacts,2MiB/file,16MiB source closure,512 relations; no archive extraction or SUT binary bundle. Root and service cases with the same bare test ID have different qualified identities and cannot borrow each other's evidence.

A versioned main-repository lock cannot embed its own commit hash. Its protected checkout revision **X** is supplied independently and includes the committed lock. Referenced root testware may use explicit reachable ancestor **A** only when **committed blob A == committed blob X == safe current bytes == declared SHA** for every root input. The current lock must equal its committed blob at X. Service repositories have no ancestor exception: checkout HEAD equals locked source commit. The receipt separates lock/composition-root X from per-artifact source-testrepo A. A test repository commit never substitutes for expected/actual deployed SUT revision. Changed X blobs, dirty locks, nonancestor refs and wrong protected/service HEADs block.

Source admission means `ADMITTED`, not approved execution. Execution binding stays `NOT_EVALUATED` until separately matching actual SUT/readiness facts. Source-class runs report `SOURCE_CLASSES_UNBOUND_UNTIL_ACCEPTED_D2_JAR`; they do not invent producer JAR/source pins. P2 consumes exact versioned metadata from a protected pinned framework process, not an uploaded self-claimed validation receipt and not core Boot-JAR internals. Do not implement a second lock/root/assembler in the consumer.

`runner-observe-producer` takes no input options and reports only the loaded class CodeSource. Supported local thin-JAR and observed Spring Boot nested-CodeSource forms hash the actual outer JAR with a96MiB streamed ceiling, bounded manifest/version parsing and exact packaged `schemas/source_bindings.v1.schema.yaml` byte identity. Nonregular/linked/mutated/oversize JARs, missing resources and unsupported locations remain `PRODUCER_UNBOUND`; class directories remain `SOURCE_CLASSES_UNBOUND_UNTIL_ACCEPTED_D2_JAR`, with null version/JAR/schema authority. `JAR_OBSERVED` is observation only. A consumer must independently bind the expected JAR SHA and exact runtime schema SHA before trusting the process envelope; no receipt can promote itself to pinned/READY. Source commit/tree remain unknown/null and are supplied separately by accepted source/build provenance, never inferred from cwd or untrusted manifest Git strings. Runtime schema resources are copied without filtering.

## Collection and retained verdicts

[Collection spec](../02-architecture/contracts/runner_collection.v1.schema.yaml) admission is independent of bundle/request content:

```text
regress runner-import --collection-spec <spec.json>
  --expected-spec-sha256 <independent-spec-pin>
  --source <owned-exported-output-root> --out <fresh-private-output>
```

`runner-export` uses the same finite collection path for an owned local snapshot. These commands do not contact a remote runtime. `runner-execute` blocks because no independently accepted native image/context/secretref/TLS/SUT transport is bound. Public external_runner/kubernetes_runtime/vm_runtime remain contract_only; the module's local-only tuple/SIT/lease gates remain unchanged. The injectable controller state machine has offline contract tests, not native container/Kubernetes/VM acceptance. A local process or fake API is never remote PASS.

A spec names only finite approved files/roles: canonical/index/summary/evidence, original producer reports, existing coverage pairs/instrumentation, bounded logs/runtime facts. Every file is length/SHA checked. Parent/final symlinks, hardlinks, special files, traversal, duplicate/reserved paths and private config/secret paths are refused. Missing/invalid/partial files remain explicit. Canonical bytes are never masked/rewritten: suspected secrets reject publication; only auxiliary logs receive a separately hashed derived mask. Entire PEM/private-key-marked logs, including truncated markers, are excluded rather than retaining their bodies. Original and saved identities remain separate.

Total retained budget64MiB includes5MiB reserved for bounded metadata and, when canonical projection is requested,16MiB reserved for the derived pair. Metadata files are individually2MiB;4096 entries include directories and reserved sidecars. Ordinary files4MiB; exact selected reviewed-gRPC canonical result8MiB. Logs are1MiB/stream,4MiB total and2000 lines. Overlimit logs are explicitly unretrieved rather than unbounded reads; no chunking bypass. Collection deadline is1..30000ms. No source tree glob/copy or tar extraction is used.

Relative canonical closure is checked before existing framework evidence/report validators. Existing evidence IDs resolve through the bounded index, not arbitrary filenames. A producer absolute-link report remains byte-exact, with original link revalidation explicitly blocked. For a valid retrieved relative graph, existing C2 creates a distinct controller-derived coverage JSON/Markdown pair outside canonical trees; producer source/version fields remain their original values and absent fields stay unknown. A valid producer FAIL remains failed, independent of runner exit/collection status. Missing canonical/coverage cannot create PASS or fabricate requirement inventory/native-agent coverage.

The receipt separates execution, runner exit, framework verdict, collection COMPLETE/PARTIAL/INVALID, validation, publication and cleanup. Public diagnostics use finite reason codes and fixed owner actions; parser snippets, exception messages, unknown keys and private paths are not echoed. A collector-only byte save with verdict UNKNOWN is not a successful product-verification receipt. Private fresh output, file/directory/parent sync and hash reread precede completion markers. A completion-marker write/force/final-readback failure invalidates only that newly owned marker, retains collected/source evidence and propagates failure; it cannot acknowledge or clean up an owned workspace. The controller acknowledges saved evidence before owned cleanup; failure/timeout collects available evidence and retains incomplete/unsaved workspaces. An unconfirmed owned stop still attempts bounded collection, prevents ACK/cleanup and retains the workspace; the controller requests stop at most once. Cleanup failure is retained separately and cannot change canonical outcomes. Source admission/collection never deletes SUT/shared resources.

## CI staging and runtime limits

`python3 scripts/ci/stage-runner-evidence.py --source <saved-collection-root> --expected-receipt-sha256 <protected-receipt-pin> --output target/runner-artifact-stage/<run-id>` stages only receipt-bound SAVED file bytes plus bound controller-derived pairs and safe receipt metadata. Unlisted files are excluded. Aliases lacking a receipt-bound digest are not staged. Staging is not a verdict gate. This utility is offline only: **CI_D2_PUBLICATION_NOT_WIRED / NOT_RUN**. The new D2 GitHub/Azure upload paths are deferred until a protected independently pinned receipt/catalog binding can be validated immediately before publication into a fresh owned stage. Current workflows preserve their existing baseline behavior and do not publish a D2 stage. Never trust preexisting target/runner-artifact-stage contents or derive the expected trust pin from the receipt being validated. Raw logs/artifacts remain in bounded evidence storage; PK receives only metadata/links through a separately authorized workflow.

The existing protected native-REST CD wrapper is separate. It requires a legal `--bundle` with framework JAR plus1..8 real readiness SPI JARs and suite files totaling<=96MiB; no new flags/validation waiver or no-JAR ConfigMap shortcut. Actual sizes and ConfigMap data/serialized size must be measured. Image runtime/framework/wrapper/adapters/collector is separate from externally pinned test input groups and SUT; image/publication/Job/PVC/transfer operations need separate concrete authorization and bindings.

One public235-byte payload completed a user-mediated base64 text roundtrip in November2026, with exact echoed byte/SHA comparison. That observation proves only that sample's text roundtrip: no capacity bound, durable receiver SAVE/fsync, native attachment, complete report/log/evidence/coverage retrieval or Kubernetes/VM runner execution follows from it. Earlier frozen P0 artifacts retain their original historical status; the later text receipt does not turn their offline tests into native runtime proof.

This extends the existing gTAA/CT-GenAI mapping: product-owned definitions and independently reviewed oracles -> existing runner/assertions -> provider SUT adaptation -> immutable evidence/typed coverage -> bounded CI/Swarm interpretation. Source file+commit -> payload/overlay -> target agent/Skill -> publication -> loaded proof -> actual run remains the source-to-effective chain. These deterministic source/offline checks do not prove native-agent loading or analysis quality.
