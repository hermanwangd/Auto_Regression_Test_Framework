# External runner operation boundaries

Defaults are disabled. No SUT, test case, oracle, data, private PK or secret is embedded in the chart or image. Bind an immutable image reference, independently pinned framework/wrapper/runtime, an external readonly case/config/data/handoff bundle and exact SUT deployed revisions before any authorized run. Source test-repo revision and deployed SUT revision are separate identities. Missing or mismatched bindings block admission.

The Helm chart composes only the fixed existing image CD entrypoint or accepted runner-import collector. It emits no Secret, RBAC, ServiceAccount, hostPath, host networking, hook or TTL cleanup. Preprovisioned input/output claims must be distinct; input is readonly and output remains retained. Nonroot UID65532 writable storage must be proved by the operator. The chart does not chown storage, create PVCs or repair cluster policy. Nonempty secret refs remain unsupported until an independently reviewed materializer exists; no plaintext secret values or arbitrary commands/env are admitted.

The Ansible role stages only externally pinned regular input files, delegates execution/collection to the existing wrapper/framework, independently validates receiver bytes/identity and requires a protected ACK before exact owned-directory cleanup. Timeout/log overflow prevents command success even if raw child exit is zero. A failed or guarded command may still collect evidence and later clean its exact owned resources after independently validated SAVE/ACK and proven stop. Unknown process identity, missing child observation, partial SAVE, stale/mismatched receipt, symlink/traversal, incomplete cleanup catalog or uncertain ownership blocks cleanup eligibility. Preserve available failure/timeout evidence first. Raw child exit and canonical product verdict remain separate from collector completion and coverage validity.

Native SSH transfer is BLOCKED until immutable source isolation, protected target identity and in-transfer byte/deadline enforcement are available. Full K8s remote retrieval is not implemented; a PVC-local collector or Pod stdout does not prove that the receiver saved all files. Keep source PVCs until independent receive/hash validation and ACK. No automatic label-wide or namespace cleanup is supplied.

Choose run-specific image pull policy only after checking actual image/ref identity, kubelet verification policy and image-record accessibility. CRI local presence alone is insufficient. The reported Kimi BusyBox Never failure was a specific credential-record mapping issue, not a universal rule for imported images. Proposed remote retries/outbound actions require their own authorization; this package performs none.

Task-private historical reproduction scripts, installed-tool state and generated coverage/log files are intentionally not included. Public test fixtures and unit status models are contract examples, not deployment readiness or product PASS.
